# Vault 三键运行：接入与交接

适用范围：Robinhood Chain **46630**，TSLA／AMZN 单笔持仓。用户通过自己的钱包完成 `Deposit → 买入`，`Stop → 暂停并撤销旧执行授权`，`Withdraw → 卖出全部持仓 → Close → 返回剩余资金并释放全部 PASS`。首次 Deposit 创建 Vault；追加 Deposit 只买新增存入的金额。Close 包括亏损后的 PASS 释放，返回的是剩余资金，并不承诺本金不亏损。

本期不需要 EMA 分钟行情、自动策略、独立股票交易 executor 或新的 executor grant。估值读取余额和价格，不签名、不广播交易。股票代币仍是现有部署中的链上测试资产，不提供真实 TSLA／AMZN 股东权益或股票托管。

## 现在缺什么

`tools/launch-market/server.ts` 默认没有行情或 keeper 发布器。新增的 `AF_STOCK_DATA_CREDENTIALS` 只接只读行情，`VaultReferenceDemand` 的 keeper 仍未配置，也没有 refresh 发布回调。仅添加环境变量、注册行情账户或准备私钥，不会使交易进入 READY。存款入口在真实可执行报价不可用时拒绝开始，避免只存资金却无法买入。

现有行情适配器是 `VerifiedStockReference`：读取 Alpaca 的交易时钟、当日日历和 IEX 最新买卖报价，核对常规交易时段与新鲜度，再生成 feed 的 `updateSession`／`update` 请求。`tools/launch-market/stock-reference.ts` 目前只生成待签名请求，不会签名或上链；页面用的展示行情接口不能代替这项交易依据。

已记录的现有 feed keeper 是 **`0x86767116cd40bf6b4f8cf88E08D11E38B04364Cf`**，由用户自己的钱包签名，同时也是 reserve owner／creator 管理地址。上线下一项能力前必须重新只读核对实际角色、feed、储备与 manifest，不把历史读数当成当前就绪证据。

## 用户现在需要做的事

1. **确定可以公开发布的行情来源。** 当前适配器支持 Alpaca IEX，至少需要 TSLA／AMZN 最新买卖报价、交易时钟及当日日历访问权。向供应商明确说明“向公开区块链写入派生价格、时间与摘要，并展示用户 Vault 估值”，取得适用的许可或合同说明，再提供供应商名称和授权文件路径。Alpaca 官方的一般 API 条款不允许通过自己的平台再分发行情；普通个人账户或买入付费套餐不能直接视为已经取得本项目的公开使用授权。[官方分发说明](https://alpaca.markets/support/redistribute-alpaca-api)
2. **在浏览器录入行情凭据，由服务器保存。** 使用 [Alpaca 注册入口](https://app.alpaca.markets/signup)及[账户控制台](https://app.alpaca.markets/account/login)生成 API Key／Secret，现有适配器使用 Paper 账户的时钟和日历。Alpaca 文档的 ReadMe 登录不是行情账户控制台。打开项目的 `#/account/market-data`，用上述管理员钱包签名登录，在两个密码框中填写凭据并保存；用户无需 SSH 或访问服务器文件系统。接口只接受已认证的管理员钱包与一次性保存请求，凭据直接经 HTTPS 写入服务器固定私密文件，目录 **0700**、文件 **0600**，不进入聊天、Git、响应或日志，也不存到浏览器持久化存储中。已存凭据不会回显。该操作只保存，页面明确显示只读行情和买卖均未启用；保存后再进行来源权限与接入核对。API Key 本身可能拥有其他供应商权限，应用的只读用途不等于供应商保证其权限只读。[认证方式](https://docs.alpaca.markets/us/docs/about-market-data-api)
3. **钱包签名能力已确认，不需再次提供现有地址或确认。** 用户继续使用上述地址的浏览器／硬件钱包。当前管理钱包私钥、助记词和解锁密码不交给服务器，也不复用现有 quote／claim voucher 密钥。下面两条路线所需的交易由 Codex 先准备成可审阅请求，再由用户钱包确认；若选独立 keeper，届时只需新增它的公共地址与保管方式。
4. **领取测试 ETH。** 管理签名钱包、实际发交易的普通用户钱包，以及未来独立 keeper 钱包都需要本链 gas。使用[官方水龙头](https://faucet.testnet.chain.robinhood.com)，领取后确认钱包网络为 **46630**、币种为 **ETH**，并以本链回执核对到账。不要把主网 4663 的 ETH 当作本链 gas。水龙头本次未实际领取或验证到账；官方仍列出测试网和水龙头，测试代币没有现实价值。[网络配置](https://docs.robinhood.com/chain/add-network-to-wallet/)、[官方测试网说明](https://robinhood.com/us/en/support/articles/robinhood-chain-testnet/)

现在先确认供应商的适用使用许可，并在管理员网页保存凭据即可。许可说明可以用普通附件交接，凭据值不要通过聊天交接。现有签名地址与签名能力已经记录；测试 ETH 余额由 Codex 只读核对，不足时再按实际发交易的钱包领取。现有 RPC 先复用，出现限流后再交接备用 RPC 的私密配置路径。

## 免费额度和收益刷新

多家供应商可组成主源与备用源，但本期仅 TSLA／AMZN 两个标的，先复用一家的服务并共享缓存。每个标的 30 秒取一次报价为 **4 次报价请求／分钟**；现有适配器逐标的读时钟与日历时，总计约 **12 次读取／分钟**。这是持续读取的预算模型，实际按需读取、休市、缓存及没有持仓时会减少请求。行情服务和链上 RPC 的额度分开计算；不能把行情请求额度当作 RPC 余额。

Alpaca Basic 免费提供 IEX 实时覆盖和 30 个 WebSocket 标的，文档的历史 API 限额为 200 次／分钟；接入后应以实际端点的限流响应头核对配额。Twelve Data Basic 的 REST 额度是 8 credits／分钟、800／天，按每标的每次 1 credit、两个标的每 30 秒一次、常规交易日 6.5 小时估算为 **1,560 credits／日**，因此不能直接把它的个人免费 REST 档视为整天备用源。Alpha Vantage 普通免费档为 25 次／天，实时及 15 分钟延迟美股数据另有付费权限。各家的私人使用档并不自动授权本项目公开展示或价格上链。[Alpaca 说明](https://docs.alpaca.markets/us/docs/about-market-data-api)、[Twelve Data 额度与用途](https://twelvedata.com/pricing)、[Alpha Vantage 说明](https://www.alphavantage.co/support/)

用户已明确选择保留 **30 秒刷新** 总资金与收益率，成交后立即刷新；接通行情后沿用这个频率。观看收益不发链上交易，Deposit／Withdraw 按用户动作和实际链上确认完成。凭据保存页只负责私密保存，不启用行情读取、价格发布或买卖。

实际可配置的只读项为 `AF_STOCK_DATA_CREDENTIALS=/绝对路径/stock-data.json`，环境变量只放路径。许可与文件权限核对后，Codex 负责把路径加入服务配置。加载文件不启动 worker，也不签名；当已有持仓缺少新鲜链上价格时，估值接口可取该来源的真实 OPEN 报价。休市只返回没有新报价，保留此前带时间的旧估值并标示过期；不会制造新价格。该配置启用的是估值读取，**不能单独使 Deposit／买卖变为可用**。

## 报价发布方式

| 方式                                      | 用户需要做什么                                                                                             | Codex 还需要做什么                                                                                                                                                                                    |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 保留现有 keeper，由用户亲自签价格更新     | 控制上述管理地址的钱包，审阅并确认真实行情生成的 feed 请求；签名前确认 chain 46630、目标 feed、金额与时段  | 接通行情授权检查与只读获取、钱包审阅／签名通道、canonical 回执和报价新鲜度检查，再接 `VaultReferenceDemand.refresh`。现有 unsigned CLI 不是完整按需发布器                                             |
| 使用独立、权限受限的 keeper，完成按需发布 | 在自己的钱包工具中准备独立 keeper 公共地址；审阅新部署、必要储备资金和迁移安排。管理主密钥继续留在用户钱包 | 提交分离权限的部署方案与交易包，核对新合约、角色、代码哈希和 manifest；实现仅准许 feed 方法的独立签名边界、限额、nonce 与回执对账，再接按需 refresh。独立 keeper 的保管和激活方式在这个具体方案中确定 |

**现有 feed 的 `keeper` 是 immutable，不能直接换一个地址。** Reserve 的 feed 以及 Factory 的策略路由也在部署时固定。第二条路线需要新的 feed／reserve／factory 路由与部署核验，不能只改一行配置。任何已有 Vault、持仓、资金和 PASS 锁定都必须保留；切换前需要明确旧 Vault 的退出路径，不能覆盖账本或把新 manifest 视作已完成迁移。

现有 `StockAutomationWorker` 明确拒绝 `keeper == operatorOwner`（`STOCK_FEED_AUTHORITY`），因此不能把当前管理钱包主密钥放进 worker 并启动它。该 worker 的连续策略运行也不属于本期单笔 owner 流程。第一条路线只由用户钱包签明示的 feed 更新；第二条路线需要完成上述独立签名与合约安排。两条路线都还需要代码接线和必要验证。

feed 价格和时段证据最多只有 60 秒有效期。人工签名、链上确认或用户钱包审阅超过有效期时，需要重新获取、审阅并更新；不能为了让按钮可用延长旧价格、伪造开市时段或让休市行情成交。

## Codex 下一步负责的工作

1. 只读复核当前部署的 keeper／owner、Factory 路由、储备余额和未完成订单，输出适用的签名与部署方案。
2. 在用户交接许可与凭据路径后，验证真实 TSLA／AMZN 报价、时钟、日历和请求限额；如供应商或许可不同，补相应适配器。
3. 实现选定的按需报价发布通道，确认 source 和授权 signer 均可用后才接入 `VaultReferenceDemand.refresh`。估值接口保持只读；不会因查看页面触发 feed 签名或股票交易。
4. 用户审阅所需交易、费用上限与实际权限后，完成该方案的配置和接线；普通用户的钱包继续自行签 CREATE、token approval、DEPOSIT、BUY／SELL、REVOKE 和 CLOSE。
5. 针对新接入验证开市／休市、过期报价、缺少资金或权限、Stop 后不发后续订单、提交结果未知不重发，以及盈利／亏损全退出。必要检查通过后发布，并以实际 source、feed 和交易回执判定 READY。

这些步骤尚未激活任何 keeper、worker、合约部署或资金交易。准备配置与文档不代表真实买卖已可用。
